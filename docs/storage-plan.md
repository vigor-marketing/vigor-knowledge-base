# 存储规划与容量管理

## 数据位置与职责

| 数据类型 | 位置 | 用途 | 是否可作为文件原件唯一副本 |
| --- | --- | --- | --- |
| 上传资料原件及历史版本 | 专用对象存储（COS） | 面向大文件与长期留存 | 是 |
| COS 对象前缀 | `{prefix}/documents/{documentId}/versions/{versionId}/source` | 每次更新创建独立版本对象，不覆盖旧版 | 是 |
| 文档元数据、分类、版本号、评论与建议 | MySQL 持久化卷 | 查询、权限和业务记录 | 否，需每日备份 |
| 向量索引 | Qdrant 持久化卷 | AI 检索加速；可由已发布资料重新建立 | 否 |
| 入库任务与短期缓存 | Redis 持久化卷 | 队列和短期状态 | 否 |
| 临时解析文件 | 容器临时目录 | 解析时短暂使用，任务完成后清理 | 否 |

## 容量原则

1. 所有用户上传的原始文件只存 COS，禁止将原件写入容器层或 CVM 工作目录。
2. 更新文件时新建 `versionId`；下载中心显示“第 N 次更新”和更新时间，并可回溯历史版本。
3. MySQL 仅保存对象键、文件大小、哈希、分类、版本、权限与评价建议；不保存二进制文件。
4. Qdrant 仅保存可重建的文本块与向量；不得作为唯一数据来源。
5. Redis 仅保存任务状态，不存文件内容。

## CVM 磁盘与扩容阈值

CVM 只用于运行服务与索引，不用于资料原件。

- 70%：告警并检查 Qdrant、MySQL、Docker 镜像与构建缓存。
- 80%：停止新增大批量入库任务，先扩容或迁移状态数据。
- 85%：仅保留下载与查询；暂停上传，完成扩容后再恢复。
- 资料量持续增长时，新增云硬盘并挂载到 `/srv/knowledge-base-data`，将 MySQL、Qdrant 与 Redis 改为明确的 bind mount；COS 无需迁移。

## COS 保留与备份

- `documents/`：保留已发布资料的全部历史版本；删除/下架应标记业务状态，不直接删除对象。
- `system-backups/mysql/`：每天一次 MySQL 逻辑备份，保留 35 天。
- `system-backups/qdrant/`：每周一次 Qdrant 快照，保留 8 周；索引损坏时也可从 COS 原件重建。
- `system-backups/manifests/`：每天导出对象键、哈希、版本和分类清单，用于恢复校验。
- 备份写入与资料原件分离的 COS 前缀；至少每季度执行一次恢复演练。

## 上线前检查

- [ ] COS 生命周期规则不会误删 `documents/` 下的有效历史版本。
- [ ] COS 凭据仅存在于 CVM 的 `.env.selfhosted` 或实例角色中，不提交 Git。
- [ ] 上传后校验对象键、文件大小与 SHA-256。
- [ ] 下载通过短时签名 URL，不公开桶读权限。
- [ ] 已设置 70% 磁盘告警及 COS 容量/费用告警。
- [ ] 已验证 MySQL 恢复、Qdrant 重建和至少一个历史版本下载。
